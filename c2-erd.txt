การพัฒนาแอปพลิเคชันให้สมบูรณ์ในระยะถัดไป

5.1     สรุปผลการดำเนินงาน
         โครงงาน Pacegasus มีวัตถุประสงค์เพื่อออกแบบและพัฒนาแอปพลิเคชันวิ่งที่ผสาน Adaptive Training
Engine เข้ากับระบบ Gamification และระบบสังคมบนพื้นฐานทฤษฎีการกำหนดใจตนเอง (SDT), ในระยะปัจจุบนั
โครงงานได้ดำเนินการเสร็จสิ้นในส่วนสำคัญดังนี้
           5.1.1 การศึกษาทฤษฎีและสังเคราะห์กรอบแนวคิด: รวบรวมและวิเคราะห์วรรณกรรม 11 รายการ
เพื่อสร้างฐานข้อมูลด้านจิตวิทยาการออกกำลังกาย (SDT, BCTs) และวิทยาศาสตร์การกีฬา (Session-RPE, ACWR)
        5.1.2 การวิเคราะห์ความต้องการและการทดสอบทางเทคนิค: กำหนดกลุ่มเป้าหมายนักวิ่งระดับปาน
กลางและจริงจัง และประสบความสำเร็จในการทดสอบเชื่อมต่อข้อมูลผ่าน Strava API ด้วย OAuth 2.0 ซึ่งช่วยให้
ระบบดึงข้อมูลกิจกรรมการวิ่งมาประมวลผลต่อได้โดยอัตโนมัติ
        5.1.3    การออกแบบระบบเชิงรายละเอียด (System Design)
               5.1.3.1 จัดทำ Hi-fidelity Prototype บน Figma ครบถ้วนทุกหน้าจอสำคัญ เช่น หน้า
        Onboarding 4 ขั้นตอน และหน้าจอการวิ่งแบบเรียลไทม์
               5.1.3.2 ออกแบบสถาปัตยกรรมระบบและฐานข้อมูลเชิงสัมพันธ์รวม 30 ตาราง พร้อมเอกสาร
        UML (Use Case 12 แผนภาพ และ Activity Diagram 13 แผนภาพ) ที่ครอบคลุมทุกฟังก์ชันการทำงาน

5.2     การอภิปรายผล
          5.2.1 ความยืดหยุ่นในการติดตามกิจกรรม: ระบบ Pacegasus ถูกออกแบบมาให้รองรับทั้งการใช้ เซนเซอร์
GPS และ Accelerometer ในตัวสมาร์ตโฟน ทำให้ผู้ใช้สามารถเริ่มใช้งานได้ทันทีโดยไม่ต้องพึ่งพาอุปกรณ์เสริม
ภายนอก, นอกจากนี้การเชื่อมต่อกับ Strava API ยังช่วยสนับสนุน ความรู้สึกเป็นอิสระ (Autonomy) ตามทฤษฎี
SDT เนื่องจากผู้ใช้สามารถเลือกใช้แอปพลิเคชันที่ตนเองถนัดในการบันทึกข้อมูลได้
        5.2.2 การเข้าถึงเทคโนโลยีสุขภาพ: จากการวิเคราะห์เปรียบเทียบกับแอปพลิเคชันอื่นในตลาด พบว่า
Pacegasus มีจดุ เด่นในการบูรณาการเอนจินปรับแผนฝึกเข้ากับระบบ Gamification โดยไม่จำกัดการใช้งานเฉพาะ
สมาร์ตวอทช์ราคาสูง, ซึ่งช่วยลดอุปสรรคในการเข้าถึงและส่งเสริมพฤติกรรมสุขภาพในระดับประชากรได้ดียิ่งขึ้น
                                                                                                        117




         5.2.3 การออกแบบที่เน้นสมรรถภาพและความปลอดภัย: การใช้คา่ Session-RPE และ ACWR มาเป็น
กลไกหลักในการคำนวณภาระการฝึก          ช่วยให้ระบบสามารถประเมินความเสีย่ งต่อการบาดเจ็บและปรับแผนฝึก
รายวัน (Missions) ให้เหมาะสมกับสภาพร่างกายของผู้ใช้ในสภาวะ Flow State ได้อย่างแม่นยำ
5.3      ปัญหาและอุปสรรคที่พบ
       5.3.1 ความซับซ้อนของข้อมูล (Data Inconsistency): ข้อมูลกิจกรรมที่ดงึ มาจาก API ภายนอกอาจมี
ความละเอียดของข้อมูลต่างกัน ซึ่งอาจส่งผลต่อความแม่นยำในการคำนวณภาระการฝึก
         5.3.2 ขอบเขตงานที่กว้างขวาง: การพัฒนาทั้งโมดูล AI Coach, Gamification และระบบสังคมพร้อม
กัน เป็นความท้าทายอย่างมากสำหรับทีมงานขนาดเล็กในการบริหารเวลา
5.4      ข้อเสนอแนะ
         5.4.1    ข้อเสนอแนะสำหรับการพัฒนาในระยะถัดไป
                   5.4.1 การออกแบบ UX/UI: ควรเน้นให้หน้า Wellness Check-in ใช้งานได้รวดเร็ว (ไม่ควรเกิน
         30 วินาที) โดยใช้ Visual Scale เพื่อเพิ่มอัตราการรักษาผูใ้ ช้งาน (Retention Rate)
                   5.4.2 กลยุทธ์ Adaptive Training: ในช่วงแรกควรเริ่มด้วยกฎแบบ Rule-based (ACWR) ก่อน
         แล้วจึงค่อยเปลี่ยนเป็น Machine Learning (Random Forest) เมือ่ มีข้อมูลผูใ้ ช้จริงสะสมเพียงพอ
